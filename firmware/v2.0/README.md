## 这一版到底是什么

上一版（v1.3）是往旧结构上打诊断补丁。这一版是**把整个板级层重写了一遍**：
音频所有权、缓冲策略、重采样器、按键分发、电台列表全部换成新结构，旧文件净减约 1250 行。

实测效果（发布者自测，两处老问题同时消失）：

- **小智不再卡顿**
- **收音机缓冲次数明显减少**

## 一、音频层重写（核心）

旧结构的问题：N32 的 UART 所有权分散在 `n32_audio.cc`（1065 行）、`desktop_codec.h` 和 AudioService
三方手里，靠「当前在哪一页」隐式决定谁能写。`desktop_codec.h::Write()` 开头那句
`if (desktop_page != 2) return samples;` 更是个**谎报**——收音机页时 AudioService 以为写成功了。

新结构：

| 文件 | 职责 |
| --- | --- |
| `audio_uart.h/.cc` | N32 半双工 UART 的唯一入口。单例 + 一把互斥锁，命令/数据都从这里出 |
| `audio_volume.h` | 音量状态与软件缩放的唯一实现 |
| `desktop_audio.h/.cc` | 桌面音效通道 `SfxChannel`，**独立任务，直写 `AudioUart`**，不跟收音机抢输出队列 |
| `audio_resampler.h` + `audio_resampler_coeffs.h` | 48-tap / 64-phase FIR 重采样，替换旧的 `q16_resampler.h`（旧的无低通，44.1k→24k 有混叠） |
| `desktop_radio.h/.cc` | 收音机页面侧接口 |
| `desktop_codec.h` | 只剩薄适配，不再谎报写入结果 |

保住的硬约束（这四条改错一条就会退步，源码里都有注释钉着）：

- `kCommandTimeoutMs = 120`（120ms 是实测 known-good，试过 40ms 会掉命令）
- **软件音量缩放必须保留**：`s = (s * vol) / 100`。N32 的 `0x14` 音量命令在流中可能不响应，不能只靠硬件音量
- 板级目录里 `abort()` / `ESP_ERROR_CHECK` 的真调用数为 **0**（以前 PSRAM 分配失败会直接 abort → 无限重启）
- 任务优先级：`audio_input=8` / `radio_feed=7` / `radio_decode=6` / `SfxChannel=6` / `radio_net=5` / `UI=5` / **`audio_output=5`** / **`opus_codec=4`**

> `audio_output` 在 v47 曾被提到 6，那次改动之后收音机开始卡——这一版保持 5。

## 二、收音机缓冲策略

| 参数 | 值 | 含义 |
| --- | --- | --- |
| PCM 环形缓冲 | **6 秒**（`kPcmCapacity = 24000×6`，288 KB，PSRAM） | 吸收网络停顿 |
| 压缩数据缓存 | 64 KB（≈8 秒 @64kbps） | 解码前排队 |
| 预缓冲 | **1.5 秒**（`kPrimeSamples`），超时 5 秒后降级到 0.5 秒 | 起播前先攒够 |
| Feed 出队等待 | 150 ms | 供给任务的节拍 |
| 送 N32 的块 | 480 样本（20 ms） | 与 ACK 节奏对齐 |

老的自持振荡链是：写失败 → 退避 300ms → 水位跌破阈值 → BUFFERING 每 50ms 轮询 → 逼近 N32 的
500ms 会话超时 → N32 判会话结束 → 冷启动重开 → 又打空。
6 秒环 + 1.5 秒预缓冲让步进幅度远超这条链的时间常数，振荡起不来。

## 三、三项交互改进

### 1. 主页：小智与游戏换位

左起 **小智 · 游戏 · 收音机 · 计时器**，与 A / B / C / D 一一对应：

| 键 | 单击 | 双击 |
| --- | --- | --- |
| A | 进小智 | 进小智并立即开麦 |
| B | 进游戏 | 直接进第一关 |
| C | 进收音机 | 直接开播 |
| D | 进计时目录 | 直达定时器并起跑 |

长按 A 仍是配网热点，长按 B/C 音量 −/+，长按 D 回主页（长按按物理键走，不跟图标走）。

### 2. 进小智页即激活聆听

以前进小智页还要再按一次 A 才开麦。现在单击 A 进入就直接起一轮对话：
状态机只在 `kDeviceStateIdle` 时才补发一次 `ToggleChatState()`，间隔 700 ms 重试，**5 秒后放弃，不会无限重试**。

> 这一项需要实机确认（激活耗时取决于服务器）。若你进去后没听到「滴」的提示音，按一下 A 仍可手动开麦。

### 3. Web 端电台列表全部可编辑（含 54 个内置台）

`http://<设备IP>/` 的收音机面板改成**逐行卡片**，每台都能改：

- 名称、地址各自可改，改完点该行的「保存」
- 每行都有「删除」
- 底部「新增电台」（追加到列表末尾）
- 「恢复内置默认电台」（带确认）

存储：NVS 键 `desk_radio/list`，多行 `名称|地址`，最多 64 台、上限 3800 字节。
旧的 `desk_radio/extras`、`custom_url`、`custom_name` 会在首次启动时自动迁移。

> 注意：**改完任何一台都会先停止播放再重建列表**（这是为了避开三任务越界，属有意设计）。
> 另外内置 54 台已经占掉约 3361 字节，距离 3800 上限只剩约 440 字节，所以能新增的台数不多。

## 四、主页图标与版式

四个图标原来是两套视觉语言混排——游戏是「奶黄实心填充 + 两个纯红按钮」，而收音机和计时器是
「青色细线描边」，游戏那枚的红色还是全组唯一的高饱和色，在深蓝底上最跳。

这一版**统一成一支笔**：

- 全部 2px 青色描边（`kAccent` 一族），背景填页面底色，**纯红已全部去掉**
- 每枚最多一处小面积暖黄（`kWarm`）点缀：手柄的功能键、笑脸的双眼、收音机的调谐灯、秒表的顶钮
- **图标改用原生 32px 绘制**。原来是最近邻放大到 36px，36/32 = 1.125 不是整数倍，
  每条边被复制的次数都不一样，所有曲线都带着一圈毛边。现在 1:1 显示，像素就是作者画的样子
- 四列重新均分：`4 + 32 + 8 + 32 + 8 + 32 + 8 + 32 + 4 = 160`，左右对称
- 顺带省掉一次启动期的 2 KB PSRAM 分配（不再需要缩放缓冲）

图标由 `tools/desk_icons.py` 用距离场（SDF）程序化生成，改图标跑一遍脚本即可，不用手改 4096 个十六进制值。

## 五、不再包含的东西

- **v1.3 的「开机诊断页 + 连续 3 次失败进 SAFE MODE」在这一版被移除了。**
  重构之后诊断信息改走 `GET /api/status` 的 `boot_reset` / `boot_seq` 两个字段
  （`boot_reset` = 上一次的复位原因枚举，`boot_seq` = 累计启动次数）。
  如果真的刷完起不来、连不上网，请直接刷回 v1.3 用它的 SAFE MODE 屏幕自诊。
- 旧文件 `n32_audio.cc` / `n32_audio.h` / `q16_resampler.h` 已删除，由上文新结构取代。

## 刷机（本板两个坑，一直没变）

1. **RTS 接不到 EN**：esptool 那句 `Hard resetting via RTS pin` 是空动作。
   **刷完芯片停在 ROM 下载模式，必须手动把电源拨 OFF 再 ON。**
2. esptool 5.6 在这块板 stub 阶段必失败，用 5.6 的 `--no-stub`（460800，2.6MB 约 3.5 分钟）。

## 刷完请这样测

1. **小智**：进小智页，看是否自动开始聆听（不用再按 A）；连续对话几轮听有没有卡顿。
2. **收音机**：连续播 3~5 分钟，期间切一次台；跑 `run-net-diag.cmd`，看 `radio_rebuffers` 是否比之前小。
3. **Web 电台编辑**：浏览器打开设备 IP → 收音机面板 → 改一个内置台的名字 → 保存 → 确认设备上名字变了。
4. **主页**：确认左起是小智、游戏、收音机、计时器，A/B/C/D 对应正确。
5. **`/api/status`**：里面新增了 `boot_reset` / `boot_seq` 和一组 `radio_*` 字段。

有任何一项不对，请把 `run-net-diag.cmd` 生成的 `ones_net_diag_*.txt` 发回。
