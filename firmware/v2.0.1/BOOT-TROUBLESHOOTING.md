# 刷完开不了机 / 不停重启怎么办

先说明一点：**这类现象绝大多数不是"刷坏了硬件"，而是完全可以通过重刷恢复的。**
设备不会因为刷固件而永久损坏——ESP32-S2 的下载模式在 ROM 里，只要芯片还能被电脑识别，就一定能救回来。

下面按"从最可能到最不可能"排，前两步能解决九成以上的情况。

---

## 第 1 步：确认不是线/口的问题（2 分钟）

"不停重启"里最常见的原因其实是**供电不足**，而不是固件：

- 换一根**能传数据**的 USB 线（很多线只能充电，或者只有两根电源线）
- 直接插**主板后置 USB 口**或**独立 5V 电源**，不要用键盘上的 USB 口、不要用延长线、不要用廉价集线器
- 换一台电脑试

供电不稳的典型特征：屏幕亮一下、暗一下、反复如此，串口日志里会出现 `brownout`。

---

## 第 2 步：擦干净重刷（5 分钟）

刷机时如果**残留了旧固件的分区数据**，会出现"新固件刷进去了但起不来"。

用发布包里的网页刷机工具：

1. 打开 `alphapi-one-s-web-flasher.html`（Chrome / Edge，需要 WebSerial 支持）
2. **勾上「擦除整个 Flash」**（重要）
3. 五段全部勾选：`bootloader.bin`、`partition-table.bin`、`ota_data_initial.bin`、应用固件、`assets.bin`
4. 点「连接」→ 选择串口 → 点「刷入」

或者用命令行一步到位（把 `COM20` 换成你的串口）：

```bat
esptool --chip esp32s2 -p COM20 -b 460800 --before default-reset --after hard-reset ^
  erase-flash
esptool --chip esp32s2 -p COM20 -b 460800 --before default-reset --after hard-reset ^
  write-flash 0x0 AlphaPi-OneS-4in1-v1.0-full-8MB.bin
```

> `erase-flash` 会清掉所有分区数据和配网信息，刷完需要重新配网。这是**刻意**的：就是要排除旧数据的干扰。

---

## 第 3 步：还是不行，就按这两条路查

### 情况一：设备起不来（屏幕黑 / 反复重启 / 连不上网）

**2.0 这一版没有开机自愈，所以不要在 2.0 上死磕——直接刷回 v1.3。**

v1.3 开机第一屏会画一屏硬件事实并停留约 1.2 秒：复位原因、第几次未确认成功的启动、
PSRAM 可用性与容量、Flash 容量、assets 分区、内部堆余量。**UI 起不来也照常显示，拍张照就够定位。**
连续 3 次起不来它会直接进 SAFE MODE 把现场停在屏幕上，不再无限重启打转。

操作：

1. 从 `firmware/v1.3/` 刷回（勾「擦除整个 Flash」）
2. 开机瞬间**给屏幕拍照**（诊断页只停 1.2 秒）
3. 把照片发回来

诊断页上这几项最关键：

| 屏上显示 | 含义 | 怎么办 |
|---|---|---|
| `RESET: PANIC` / `WDT` 反复出现 | 程序在崩溃或任务卡死 | 把屏上整页拍下来 |
| `PSRAM: NOT AVAILABLE` | PSRAM 没初始化 | 见下方「硬件批次差异」 |
| `PSRAM: 2048KB` 但 `HEAP` 很小 | 内存被吃掉了 | 拍下来即可 |
| `ASSETS: NOT FOUND` | 资源分区没写进去 | 重刷，务必带 `assets.bin` |
| `BOOT #3` 以上 | 确实在循环重启 | SAFE MODE 会停住，拍照 |
| 屏全黑、一个字都没有 | 卡在 LCD 初始化之前 | 见下方「硬件批次差异」 |

### 情况二：能开机，但某个功能不对

这时候设备是活的，**直接读 HTTP 状态**，不需要串口。

1. 确认设备和电脑在同一 WiFi（配网页能看到 IP）
2. 双击发布包里的 `run-net-diag.cmd`
3. 它会在同目录生成 `ones_net_diag_<时间>.txt`
4. **把这个 txt 整份发回来**

`/api/status` 里有用的字段：

| 字段 | 含义 |
|---|---|
| `boot_reset` | 上一次的复位原因（枚举值，`-1` = 没有记录） |
| `boot_seq` | 累计启动次数。数字一直在涨 = 确实在反复重启 |
| `psram_free` / `psram_total` | PSRAM 余量 |
| `heap_int_free` | 内部 SRAM 余量（低于 10 KB 就要留意） |
| `radio_rebuffers` | 收音机进缓冲的次数（就是用户听到的「断一下」） |
| `radio_write_fail` | 往 N32 写字节不足 → UART/N32 侧问题 |
| `radio_net_err` | HTTP 读失败 → 网络/电台侧问题 |
| `radio_dec_err` | MP3 解码失败 → 解码侧问题 |
| `radio_pcm_min` | 历史最低 PCM 水位，贴 0 = 喂不上 |

### 关于串口：这块板读不到日志，别白折腾

console 走 UART0（GPIO43），而 **UART0 没引到 USB**。板上的 USB 是原生 USB-CDC
（`VID_2F4E` / 序列号 `ALPHAPI_ONES`），只在 ROM 下载模式通，运行时没有任何日志输出。
四种 DTR/RTS 组合、各档波特率实测都是 **0 字节**。

所以这一类问题的诊断**一律走 `GET /api/status`**，不要去找串口。这也是为什么 1.3 要加屏幕诊断页。

---

## 万一是硬件批次差异

同一版型（丝印 `v1.7`）在不同批次上可能焊了**不同型号的 PSRAM 或 Flash**。这颗 ESP32-S2 的内部 RAM 只有 320 KB，
固件把 LVGL 和显示缓冲都放在外挂 PSRAM 上，所以 PSRAM 缺失、型号不兼容、或者跑不上 80 MHz 时，
表现就是"别人刷完能开机，我这台一直重启"。

判断方法：日志里出现 `psram : NOT AVAILABLE`，或者反复停在
`Failed to init external RAM`。

从 **v1.1 起固件已经做了容错**：PSRAM 拿不到不再直接 abort 重启，而是降级运行并把原因打到串口。
如果你刷的是 v1.0 且正好是这类板子，请升级到 v1.1 或更新版本。

---

## 实在救不回来

按住板子上的 **BOOT** 键（GPIO0）不放，再插 USB，然后松开——这样芯片会强制进入下载模式，
无论 flash 里是什么内容都能重新刷写。网页刷机工具在这个状态下也能连上。

如果连下载模式都进不去（电脑完全不认串口），那是 USB 线或接口的问题，不是固件问题。
